Hybrid attention + recurrent models · reviewed 21 September 2026

Where a hybrid model can pick up a cached prefix

An attention layer stores every token, so any prefix of a conversation can be reused. A recurrent layer, such as Mamba or GDN, keeps a single state that each new token overwrites. It can only resume where the engine saved a copy of that state. This page shows where vLLM saves those copies, why they sit hundreds or thousands of tokens apart, and which settings move them.

The short version. A recurrent layer resumes only from a saved checkpoint. vLLM's align mode saves one only where a scheduler step ends exactly on a block boundary. The block size, called N here, is set by how big one checkpoint is, and for these models it is several hundred to a few thousand tokens. The token budget per step then decides whether every boundary gets a checkpoint or only a few.

Why checkpoints are hundreds of tokens apart

vLLM gives every layer the same page size, so one memory pool can serve both kinds of layer.

N follows the size of the live state in GPU memory. Storing a checkpoint in a smaller format on CPU or disk does not change it; the storage section shows why.

Which boundaries actually get a checkpoint

The kernel hands back the recurrent state only at the end of a scheduler step. vLLM's align mode cuts prefill steps so that they end on block boundaries.

The rule comes from vLLM's scheduler. A prefill step that stops short of the prompt end is rounded down to a whole number of blocks, and no step runs past the prompt's last block boundary. The prompt's final partial block is left without a checkpoint. With a budget between N and 2N−1, every step covers exactly one block, so every boundary gets a checkpoint. A larger budget prefills faster, but each step then covers several blocks and only its last boundary is saved. The LMCache recipe recommends 2N−1: it keeps every boundary and leaves N−1 tokens of room so requests that are already decoding can share the step.

align is vLLM's default when prefix caching is on. The older all mode saves every boundary regardless of steps, but it is deprecated at the pinned commit and GDN backends do not support it. The 64-token chunk a GDN or Mamba kernel uses internally is unrelated to N.

This figure models one request running alone, with no speculative decoding. The pinned scheduler can add three more stopping points that are left out here: the prompt's last hash boundary when a finer prefix-match unit is configured, the point where a request was seen to diverge from an earlier one, and a checkpoint that some backends export from inside the final step.

What this calculation assumes

                    
The simplified aligned-page model is:

                    
S = recurrent matrix values × working bytes + convolution values × 2
T = KV values per attention layer per token × 2
N = A × ceil(S / (A × T))
P = N × T

                    

                        S
                        is the live recurrent payload,
                        T
                        is attention bytes per token,
                        A
                        is the assumed effective allocation alignment,
                        N
                        is the block size, and
                        P
                        is the shared page. The selected
                        A
                        stands in for backend constraints and a requested block size; it is not inferred from a GPU.
                        Additional groups, MLA layouts, quantized KV, tensor parallelism, speculative scratch state and
                        extra auxiliary state can change this calculation.
                    

                    

                        Model configuration describes dimensions; the engine resolves state dtype and layout. FP32 is an
                        explicit scenario here, not a default attributed to all four models. The Qwen config requests
                        FP32 SSM state, while the other linked configs do not establish that same request. Inspect
                        actual cache specs and startup logs before quoting a deployment number.
                    

                    

                        One live state per conversation and many retained prefix checkpoints have different memory
                        costs. If every attention block has one recurrent checkpoint and per-layer pages are equal, the
                        recurrent share is the recurrent branch count divided by the total branch count. Sparse
                        checkpoints, shared prefixes, padding and eviction change that share. Count unique retained
                        objects, and report GPU allocation, serialized bytes and transferred bytes separately.
                    

                    

                        For a real deployment, verify checkpoint positions and actual restores after GPU eviction;
                        require complete attention, recurrent and convolution state at the same boundary. Test changed
                        suffixes, exact block boundaries and missing components. Storage compression also needs quality
                        measurements at its actual store/restore cadence, including chained reuse.
