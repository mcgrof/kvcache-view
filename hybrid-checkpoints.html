Hybrid attention + recurrent models

A recurrent checkpoint is big, so reusable prefixes are far apart

Attention caches can be sliced: the entries for the first 500 tokens are literally the front of the entries for the whole sequence. A recurrent state cannot. It is one matrix that has been overwritten once per token, and there is no way to rewind it. To reuse a prefix at all, a serving engine must have stored a whole separate checkpoint at that point. How far apart those checkpoints can sit is not a tuning choice. It is set by how many bytes one checkpoint takes.

The rule. vLLM makes every layer use one page size. A recurrent page holds one whole checkpoint and does not grow with tokens; an attention page grows with its block. So the attention block is raised until one attention page is at least as large as one recurrent page, and the recurrent page is then padded to match. That block size is the spacing between resume points, and the arithmetic only ever rounds up. No setting makes checkpoints closer together while the checkpoint stays the size it is.

A cache layered on top, such as LMCache, has to pick a chunk size, and 256 tokens is a common default. It is below the spacing of every model here in every format down to 8 bits, so it would address a position where no checkpoint was ever written. The chunk has to be the spacing or a multiple of it.

Caveats

Read before quoting any number on this page.
This is arithmetic from vLLM's sizing rule and each model's configuration, not a measurement of a running server. Kernel alignment is taken as 16 tokens; a backend that demands more pushes the spacing up. The state dtype is read from configuration and can be overridden. Making the stored checkpoint smaller is not free: the page pool holds the state the recurrent kernel actually reads, so either that kernel reads the compressed form or the design separates the stored checkpoint from the live state and expands it on restore. The second has not been built. Finally, a smaller checkpoint only helps if the model tolerates the format, and that is strongly model-dependent.
