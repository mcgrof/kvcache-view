Hybrid attention + recurrent models · reviewed 20 September 2026

Checkpoint size shapes reuse. The engine decides where.

Full-attention KV preserves token history. A recurrent layer keeps a state that is updated in place; a later state cannot simply be sliced to recover an earlier prefix. Reuse needs a checkpoint at the chosen boundary, its convolution and other persistent state, and the matching attention history.

Three separate questions. How large is the engine's allocation block? Which boundaries actually get a checkpoint? How many bytes does a saved checkpoint occupy? In vLLM's aligned shared-page path, live-state size constrains the first. Scheduling and retention determine the second. A storage codec can reduce the third without changing either of the others. This is an implementation trade-off, not a universal minimum interval imposed by recurrent models.

In the ordinary align path, checkpoints are exported at eligible scheduler-step ends. A step spanning several blocks need not preserve each intermediate state. Backend-specific checkpoint exports, eviction and prefix sharing can change the available set. The older all mode is deprecated in the inspected vLLM tree; it is not a promise of dense checkpoints on current backends. A compute kernel's 64-token chunk is a separate quantity.

Separate compressed checkpoint pools already exist: SGLang merged an INT8 checkpoint pool on 18 June 2026 , retaining a BF16 working pool. That is evidence for a storage/working-state split, not for automatic finer checkpoint spacing or quality equivalence on every model. CPU or NVMe offload likewise needs the engine to supply a complete state at the advertised boundary; a faster I/O path cannot recreate a missing checkpoint.

What this calculation assumes

The simplified aligned-page model is:

S = recurrent matrix values × working bytes + convolution values × 2
T = KV values per attention layer per token × 2
N = A × ceil(S / (A × T))
P = N × T

S is live recurrent payload, T is attention bytes per token, A is the assumed effective allocation alignment, N is the allocation block, and P is the shared page. The selected A stands in for backend constraints and requested block size; it is not inferred from a GPU. Additional groups, MLA layouts, quantized KV, tensor parallelism, speculative scratch state and extra auxiliary state can change this calculation.

Model configuration describes dimensions; the engine resolves state dtype and layout. FP32 is an explicit scenario here, not a default attributed to all four models. The Qwen config requests FP32 SSM state, while the other linked configs do not establish that same request. Inspect actual cache specs and startup logs before quoting a deployment number.

One live state per conversation and many retained prefix checkpoints have different memory costs. If every attention block has one recurrent checkpoint and per-layer pages are equal, the recurrent share is the recurrent branch count divided by the total branch count. Sparse checkpoints, shared prefixes, padding and eviction change that share. Count unique retained objects, and report GPU allocation, serialized bytes and transferred bytes separately.

For a real deployment, verify checkpoint positions and actual restores after GPU eviction; require complete attention, recurrent and convolution state at the same boundary. Test changed suffixes, exact block boundaries and missing components. Storage compression also needs quality measurements at its actual store/restore cadence, including chained reuse.
