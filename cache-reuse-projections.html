PROJECTION 02 · COMPUTE, I/O & ARCHITECTURE · REVIEWED NOV 17, 2026

Will faster GPUs make KV reuse obsolete?

A faster prefill makes recomputation cheaper. A smaller saved state makes reuse faster. Put both effects on the same clock, first with the architecture held fixed, then with explicit architecture changes.

This is a sensitivity model, not a forecast. The default starts from the supplied V4.1 Flash scenario: 80,000 tokens, 890 B/token and a 26 ms recompute on eight Rubin GPUs. The 26 ms is an input to inspect, not a validated benchmark. Future annual rates are editable assumptions.

These are nominal peak rates, not measured agentic prefill throughput. Kernel efficiency, precision, tensor/expert parallel communication, weight traffic, batching and availability can change the realized gain. Dates are the hardware anchors used here, not a claim that every product shipped on January 1. Neither a faster GPU nor a wider PCIe specification guarantees a proportional end-to-end speedup.

HOW TO READ THE PROJECTION

The useful question is the work-to-state ratio

Without a fixed floor: reuse advantage ≈ (prefill FLOPs ÷ saved bytes) × (restore bytes/s ÷ effective FLOPs/s)

What extends cache reuse?

State compression that outpaces compute reduction, faster storage-to-GPU paths, larger reusable prefixes and predictable prefetch can keep reuse useful. Prefetch changes visible latency; it still consumes bandwidth and capacity.

What weakens it?

Cheaper prefill, smaller reused prefixes, slow shared links, lookup/reconstruction overhead and low reuse probability. A latency crossover is specific to those assumptions. It does not mean all KV caching becomes irrelevant.

What the future curves assume

Each year multiplies effective compute and bandwidth by their growth factors. Variable bytes shrink by their architecture factor; work shrinks independently. Optional context growth scales variable bytes linearly, and prefill by the selected mixture of linear and quadratic work. A fixed checkpoint does not shrink.

What to measure next

Match the model revision, cache format, prompt, precision and serving load. Measure full recompute and time from cache lookup to usable GPU state, including replay. Repeat under concurrent reads and writes. Use those baseline values before interpreting any projected year.

Latency is only one condition. Retaining a context also needs enough expected return value, compatible state and available capacity. The agentic economics view assesses those conditions separately, including the cost of holding one context idle.
